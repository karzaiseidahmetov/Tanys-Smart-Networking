# Tanys — AI-сервис умного нетворкинга

*«Таныс» по-казахски значит «знакомый».*

**Кейс:** Qazaq IT Community · трек *AI for Smart Campus* · AI in Engineering Hackathon 2026 (МИТУ)

Подсказывает участнику IT-мероприятия, **с кем стоит познакомиться и почему**: по профилю за ~2 мс возвращает
5 человек с объяснением, первой фразой для знакомства и свободным слотом для встречи 1:1.

> 🇰🇿 Қатысушының профилі бойынша 5 адамды ұсынады: неге танысу керек, алғашқы сөз және 1:1 кездесу уақыты.
> Интерфейс қазақ, орыс және ағылшын тілдерінде.

## Быстрый старт

**Вариант 1 — Docker**
```bash
docker compose up --build
```
**Вариант 2 — просто Python 3.10+** (внешних зависимостей нет, `pip install` не нужен)
```bash
python -m app.server
```
Откройте **http://localhost:8090**. Порт можно сменить: `PORT=9000 python -m app.server`.

Пересоздать базу профилей: `python data/generate_profiles.py`
Проверка качества и скорости: `python tests/eval.py`
**Полный приёмочный тест по всем критериям кейса:** `python tests/hard_test.py` → **223/223 проверок**
(включая мероприятия, места в зале 10/10, работу и найм 32/32, качество внутри каждого мероприятия, аккаунты, чат, мобильную версию и PWA)

| Что проверяет `hard_test.py` | Результат |
|---|---|
| Качество: 24 «анкеты жюри», в том числе сложные: только свободный текст, только казахский, сленг, капс, редкие роли, текст 2000+ символов. Каждую рекомендацию оценивает **независимый судья**, а не скоринг самого алгоритма | у каждой анкеты ≥ 3/5 подходящих, **точность@5 = 98%** |
| Взаимность: fuzz-тест на 500 случайных анкетах | 0 нарушений, соискателю ни разу не показан соискатель |
| Объяснения: 1–2 предложения, правдивость (заявленные совпадения действительно есть у обоих) | 120/120 |
| Скорость на базе в 190 и в 1000 участников | p99 ≈ 2 мс, максимум на 1000 участников ≈ 4 мс |
| Отзывы: исключение, пересчёт, история, отмена, 40 отказов подряд | без ошибок |
| HTTP: все endpoints; битый JSON, мусорные поля, чужой user_id | сервер не падает |
| XSS-экранирование, отсутствие API-ключей, README, docker-compose, CSV и JSON | ✅ |

API-ключи **не нужны**: решение работает полностью офлайн, без внешних LLM.

### С телефона
Телефон и компьютер должны быть в одной Wi-Fi сети. Откройте `http://<IP-компьютера>:8090`.
Приложение — **PWA**: в меню браузера выберите «Добавить на главный экран», и оно откроется как отдельное приложение
с иконкой Tanys и нижней панелью навигации. Установка в один тап на Android требует HTTPS
(на `localhost` или при деплое за HTTPS она работает сразу).

## Мероприятия (митапы, конференции, хакатоны)

- Вкладка **«Мероприятия»**: карточки с названием, типом, датой, местом и числом участников.
- Участник **регистрируется** на мероприятие, и подбор знакомств идёт **только среди его участников**: знакомиться можно лишь с теми, кто реально в зале.
  Название текущего мероприятия видно в шапке, на странице подбора и в выдаче.
- Можно зарегистрироваться на несколько мероприятий и переключаться между ними. Дашборд организатора и список участников строятся по выбранному мероприятию.
- Любой участник может **создать своё мероприятие** (как организатор): после создания он сразу зарегистрирован.
- Демо-мероприятия генерирует `data/generate_events.py` → `data/events.json`: хакатон (все 190 анкет) и три тематических события.
  Для каждого события действует проход покрытия: при любой роли участника в зале есть нанимающие, менторы, менти и участники обмена опытом.
  Поэтому качество держится **внутри каждого мероприятия: 95–98%, все 24 анкеты жюри ≥ 3/5**.

### Места в зале
У каждого участника мероприятия есть место: зона (A — Сцена, B — AI Lab, C — Career Hub, D — Startup Alley,
E — Кофе-зона, F — Mentor Desk) и номер стола. В карточке рекомендации написано, где сидит человек, а над выдачей
показана **карта зала**: на ней отмечены вы и ваши 5 рекомендаций (номерами). Своё место можно изменить в карточке мероприятия.
Места демо-анкет детерминированы: нанимающие и соискатели чаще сидят в Career Hub, менторы — у Mentor Desk и т. д.

## Работа и найм (без мероприятия)

Отдельная вкладка **«Работа»** работает без привязки к мероприятию:
- **Соискатель** видит вакансии, отсортированные AI по его анкете («Подходят мне»), с объяснением: роль, общий стек, уровень относительно опыта.
  Отклик в один клик автоматически отправляет автору вакансии готовое сопроводительное сообщение в чат.
- **Нанимающий** публикует вакансию (роль, уровень, формат, город, зарплата, стек), и AI сразу подбирает подходящих кандидатов
  из всех ищущих работу с объяснением. В «Моих вакансиях» видны отклики.
- Все вакансии можно искать и фильтровать по роли и формату. Анкету можно сохранить и без регистрации на мероприятие.
- Демо-вакансии генерирует `data/generate_vacancies.py` → `data/vacancies.json` (72 вакансии от демо-нанимающих).
  Проход покрытия гарантирует, что для каждой базовой студенческой технологии есть минимум 3 junior-вакансии.

## Аккаунты и чат

- **У каждого участника свой аккаунт**: логин и пароль. Пароли хранятся как PBKDF2-SHA256 с солью (120 000 итераций),
  сессии — случайные bearer-токены. Анкета сохраняется в аккаунт: при повторном входе она подставляется сама.
- **Знакомство через первое сообщение.** Кнопка «Написать» у рекомендации открывает чат, а поле уже заполнено фразой-icebreaker.
  **Правило первого сообщения:** пока собеседник не ответил, можно отправить только одно сообщение. Это защищает от спама в зале.
- Живые участники переписываются между собой: непрочитанные видны в бейдже, чат обновляется каждые 2–4 секунды.
- Синтетические демо-анкеты **отвечают на каждое сообщение** (с пометкой «демо-ответ») на языке интерфейса.
  Ответ зависит от смысла сообщения: указанное время («в 14:30») подтверждают, на вопросы о вакансиях и стеке отвечают,
  на благодарность и прощание реагируют, в остальных случаях предлагают свободный слот.
- **Галочки, как в WhatsApp:** ✓ — отправлено, ✓✓ — доставлено (приложение собеседника получило сообщение),
  синие ✓✓ — прочитано (собеседник открыл чат).
- **«Печатает…»:** когда собеседник набирает текст, это видно в чате (анимированные точки) и в списке диалогов.
- **Удаление чата** (с подтверждением): «удалить у меня» — переписка исчезает только у вас;
  «удалить у всех» — удаляется у обоих и с сервера.
- Свою анкету нельзя подменить: запросы к аккаунту без токена отклоняются (401).

## Как работает подбор

```
Профиль ──► 1. Разбор свободного текста (ru/kk/en словари синонимов) → навыки + интересы
        ──► 2. Фильтр взаимности целей (жёсткое правило)
        ──► 3. Скоринг кандидатов (6 признаков, веса зависят от цели)
        ──► 4. Учёт отзывов (исключение + сдвиг по похожим ролям)
        ──► 5. Объяснение + icebreaker + слот 1:1 + стенды
```

**1. Разбор текста.** Из поля «о себе» извлекаются навыки и темы на трёх языках, со сленгом:
«питон», «кубер», «машиналық оқыту», «финтех» → `python`, `kubernetes`, `ai`, `fintech`.
Так рекомендации работают, даже если человек заполнил только текст.

**2. Взаимность целей** (`GOAL_PRIMARY`):

| Моя цель | Кого показываем |
|---|---|
| Найти работу | Нанимающих (**никогда** других соискателей) |
| Нанять | Ищущих работу |
| Найти ментора | Готовых менторить (опыт больше хотя бы на 3 года — бонус) |
| Стать ментором | Ищущих ментора |
| Найти кофаундера | Ищущих кофаундера (технарь + бизнес = бонус за взаимодополнение) |
| Обмен опытом | Тех, кто тоже хочет обмена опытом |

Если прямых совпадений меньше 5, добавляется резервный уровень (`GOAL_SECONDARY`) с пометкой «близкий вариант».
Соискателю другие соискатели не показываются никогда.

**3. Скоринг** (каждый признак от 0 до 1, взвешенная сумма):
- `role` — совместимость ролей: нанимает ли кандидат мою роль, близкие роли (backend ↔ devops), взаимодополнение у кофаундеров;
- `stack` — пересечение навыков (косинус по множествам);
- `inter` — пересечение интересов;
- `text` — TF-IDF косинус описаний с грубым стеммингом, который работает для ru/kk/en;
- `exp` — разница в опыте для пары ментор–менти;
- `lang` — есть ли общий язык общения.

Веса зависят от цели: для найма важнее роль и стек, для кофаундеров — интересы и взаимодополнение.

**4. Отзывы.** «Познакомились» и «Не подходит» убирают человека из выдачи. «Не подходит» понижает кандидатов той же роли,
«Познакомились» повышает. Список сразу пересчитывается.

**5. Объяснения** собираются из реальных признаков, которые совпали (без LLM и без выдуманных фактов):
> *Асель Әбдірова нанимает (Backend-разработчик, ML / Data Scientist) — это совпадает с вашей ролью «Backend-разработчик». Общее: стек — python; интересы — Финтех.*

Почему без LLM: выдача детерминирована и объяснима, работает < 3 мс без интернета и ключей,
а в каждом объяснении указаны только факты, которые действительно совпали.
LLM можно подключить позже для перефразирования объяснений.

## Данные

`data/generate_profiles.py` генерирует **190 синтетических профилей** (seed 42, воспроизводимо):
14 ролей, реалистичные стеки, интересы, опыт, цель, языки, свободные слоты, текст «о себе» на ru/kk/en.
Имена **вымышленные**, собраны случайно из списков имён и фамилий. Реальные профили (LinkedIn, Telegram) **не использовались**.

Сначала генерируются 160 случайных профилей, затем идёт **проход покрытия**: для каждой профессиональной роли
гарантируется минимум 3 нанимающих, 2 ментора, 2 менти, 2 соискателя и 2 участника обмена опытом.
Поэтому даже анкета с редкой ролью (QA, ИБ, GameDev) получает релевантные рекомендации.

Распределение целей: найти работу 40 · нанять 31 · найти ментора 29 · стать ментором 26 · кофаундер 28 · обмен опытом 36.

Файлы: `data/profiles.json` (используется сервисом), `data/profiles.csv` (для просмотра в Excel).

## Структура

```
app/
  catalog.py      роли, цели, правила взаимности, словари синонимов ru/kk/en, стенды
  recommender.py  фильтр + скоринг + отзывы + статистика
  texts.py        шаблоны объяснений и icebreaker-ов на 3 языках
  server.py       HTTP-сервер (только стандартная библиотека Python)
static/index.html одностраничный интерфейс (без внешних библиотек и CDN)
data/             генератор и синтетические профили
tests/eval.py     проверка взаимности, скорости и примеры выдачи
```

## Права

Права на решение принадлежат команде.
